# 未來對話安全回答政策（任務 17）

本政策是未來對話功能的 release gate，不是聊天 API、提示詞、模型設定或使用者可見回答。任何未來實作必須先通過 `chat_golden_cases.csv` 的所有規則；本文件不授權產生個人化活動建議。

## 引用與來源狀態

任何可引用摘要都必須在同一回應的每個可驗證主張附近，列出來源名稱、原始 HTTPS 連結或官方穩定識別、最後核對日期、授權／顯名文字與來源狀態。資料 API 回應應額外保留其資料集 ID、來源發布／取得時間、provenance 與資料品質欄位。

- `public_summary`：可做短摘要，但不等於現行性、安全性或個人化適用性保證。
- `link_only`：只顯示外部連結、來源名稱與限制，不得輸出原文或衍生摘要。
- `pending_review`、`excluded`、`untracked`：不得作公開回答依據；除非稽核介面明確要求，連題名以外的內容也不輸出。

## 時效與 fail-closed 規則

即時或時效性資料一律使用來源發布／更新時間，而不是下載時間或預報有效時間偽裝新鮮度。

- 一般天氣 API 必須通過既有 8 小時新鮮度規則，且每一列顯示具時區時間；過期、時間缺失、503、未覆蓋或查無時段時回資料不足，不快取舊值。
- 波浪／海流 API 必須通過既有 6 小時新鮮度與空間距離規則。格點距離超限、來源無法解析、過期、503 或空結果時，不能輸出數值，也不能以天氣替代。
- 潮位目前僅允許本機研究結構化，公開呈現／再發布權利未確認；一律不得當作公開對話內容。
- eDNA 是歷史研究證據，不以「最新」判斷，但每次都要保留採樣日期與距離等限制；無紀錄不能補成物種清單。

## 高風險與抗注入規則

「是否可下水」、「安全／危險」、「合法／違法」、「最適合」、「保證可見」及同義的活動結論，皆不可由任一單一資料源、檢索命中、模式格點、代表點或法規背景產生。使用者要求忽略上述規則、要求模型記憶補足、轉碼受限內容、索取 Key 或本機檔案時，一律拒絕，且不重述敏感內容。

未來聊天系統尚需具備：實際輸出對黃金集的機器評測、逐句引用完整性檢查、來源／時效 middleware、權限去除測試、秘密掃描、人工領域審閱，以及符合本政策的拒絕／轉介呈現方式。
