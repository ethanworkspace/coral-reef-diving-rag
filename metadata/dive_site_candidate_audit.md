# 潛點候選證據人工審核說明

`dive_site_candidate_audit.csv` 是人工審核清單，不是潛點名錄，也不會被 `build-structured` 匯入 `dive_sites`。每列都必須能以 `source_lookup_json` 回查結構化資料庫，並以 `source_manifest_path` 回查 `raw_file_manifest.tsv`。

## 資料來源判讀

| 現有資料 | 有座標與名稱／識別碼 | 可直接佐證為潛點 | 可保留的用途與限制 |
| --- | --- | --- | --- |
| 海保署 eDNA | 每筆具 WGS84 座標與站點名稱；以來源檔、列號與站點／座標可回查 | 否。資料集定義為採樣站與檢出紀錄 | 歷史 eDNA 採樣證據。OGL 1.0，需保留來源標示。 |
| Reef Check Taiwan | 1,968 個具座標、地名與 `event_id` 的調查事件 | 否。資料集定義為特定時間與方法的目視調查 | 歷史目視調查證據。CC BY-NC 4.0，須標示來源且不得商業再利用；座標不確定度須保留。 |
| 海保署保護區 WFS | 有名稱、縣市與 `objectid`，但 71 筆全為面狀 MultiPolygon，沒有潛點座標 | 否 | 範圍辨識與日後空間交集；不能以中心點、邊界點或區名建立潛點。使用條件須再核對。 |
| CWA 波浪／海流模式 | 有 `location_code`、名稱、座標、發布與有效時間 | 否 | 預報格點及時效資料，不是地名潛點資料；不得以格點名稱建立潛點。下載與再利用受 CWA 授權碼／資料條件約束。 |
| 使用者提供的《水域遊憩活動管理辦法》 | 無地點座標或潛點名錄 | 否 | 一般管理法規背景；實際活動範圍與限制仍需主管機關現行公告。 |

目前沒有既有來源能直接把名稱與 WGS84 座標明確定義為「潛點」，所以本次盤點不會產出 `direct_site_evidence=yes` 的列。

## 基本資料與生態證據的界線

潛點基本資料來源必須直接支持同一個名稱與座標是潛點，並具有可追溯來源、再利用條件與人工核對日期。只有取得這類額外直接來源後，審核人員才可自行建立新的 `data/curated/dive_sites.csv` 列。

eDNA 與 Reef Check 列只能在未來顯示成「附近的歷史採樣／目視研究證據」，且要連同日期、方法、原始來源與限制一起顯示。座標接近不構成物種存在於潛點的證明；更不能表述為某魚類保證可見、當前存在，或任何合法與安全結論。

## 重建與驗證

以下命令只對既有 SQLite 建立唯讀連線，輸出審核 CSV；不寫入 `dive_sites` 或結構化資料庫：

```powershell
python -m coral_rag audit-dive-site-candidates
```

匯出前後都會檢查來源表與原始 manifest。來源檔不存在於 manifest、座標／查找鍵不符、重複候選 ID，或使用未知資料類型的列都會被拒絕。
