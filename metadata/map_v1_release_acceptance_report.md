## 2. 模組驗收結果清單

本驗收嚴格區分「**通過**」、「**已修正 UI 缺陷**」與「**資料來源缺口**」，不將資料缺口包裝為功能已完成。

### 2.1 潛點與地圖呈現（狀態：通過）
- **潛點收錄專屬性**：
  - 地圖互動標記與清單**僅呈現正式潛點庫中已核驗的 5 筆**（石朗潛水區、綠島南寮漁港、柴口浮潛區、大白沙、險礁嶼）。
  - API 端點 `/api/dive-sites` 回傳數量精確為 5 筆，且資料品質標記為 `source_verified`。
- **代表點空間語意與安全防線**：
  - 介面與 API 回應明確標明：**「此座標為景點代表點，不代表下水入口、活動範圍、合法性或安全條件」**。
  - 地圖標記點擊與清單按鈕雙向綁定，選取潛點時名稱、座標與資訊抽屜保持完全一致。
  - 支援鍵盤瀏覽（Tab、Enter）、焦點跳轉與 `skip-link` 略過至潛點清單。

### 2.2 海況資訊與數值模式隔離（狀態：通過）
- **外海數值模式明確標籤**：
  - 資訊卡標題嚴格使用「**附近海域模式參考（非潛點現場量測）**」，資料性質標為 `nearby_numerical_model_context_not_in_situ_observation`。
  - 清晰呈現模式計算點代碼／名稱（石朗海域 N01900、柴口海域 N01600、龜灣海域 N01800、赤崁 I01700）、模式點座標、發布時間、有效時段及與潛點直線距離（1.79 km 至 2.66 km）。
- **嚴格排除現場與安全推論**：
  - 介面與 API 完全不包含「現地量測」、「適合下水」或紅綠燈安全判定。
  - 固定警示文字聲明外海巨觀預報無法反映近岸水文微地形、碎波帶與暗流。
- **時效性與快照閘門**：
  - 當快照超過 24 小時或雜湊損毀時，API 嚴格 fail-closed 回傳 HTTP 503，介面顯示不可用提示，絕不顯示過期舊預報。

### 2.3 歷史生態證據與物種參考圖片（狀態：通過）
- **物種參考圖檔專屬性**：
  - 石朗潛水區：呈現 2 筆已核准之 eDNA 對照（線紋刺尾鯛、克氏雙鋸魚），標示為「水樣 DNA 分子訊號」，具作者、CC 授權與 Wikimedia 來源頁。
  - 柴口浮潛區：呈現 1 筆已核准之 eDNA 對照（七帶豆娘魚），標示為「水樣 DNA 分子訊號」。
  - 大白沙：Reef Check 棘冠海星（`LINK-SP-EVD-004`）受 CC BY-NC 4.0 授權限制，在預設伺服器部署下**嚴格關閉（0 筆）**；呼叫端傳入 `?research_mode=true` 完全無法覆蓋，僅在伺服器端環境變數 `REEFCHECK_LOCAL_NONCOMMERCIAL_RESEARCH_MODE=enabled` 下始開放檢視。
  - 綠島南寮漁港與澎湖險礁嶼：維持 0 筆合格圖片，介面呈現明確無資料提示，嚴禁使用推測圖片。
- **杜絕珊瑚物種偽造**：
  - 珊瑚生態僅依現有證據描述歷史硬珊瑚覆蓋度或官方環境特色文字；在無物種級精確證據前，**絕對不列出虛構之珊瑚物種清單**。
- **外觀參考固定聲明**：
  - 每張圖片均配置橘黃醒目標章與固定用途文字：**「物種外觀參考（非潛點現場拍攝，亦不代表該物種目前可見）」**。

### 2.4 易用性、無障礙與安全防禦（狀態：通過）
- **零 innerHTML 政策**：
  - 前端程式碼全面採用 `document.createElement`、`textContent` 與 `replaceChildren`，根除 DOM XSS 風險。
  - 所有外連連結強制具備 `target="_blank"` 與 `rel="noopener noreferrer"`。
- **無障礙標籤與焦點管理**：
  - 地圖配置 `role="region"`、狀態訊息配置 `role="status"` 與 `aria-live="polite"`。
  - 支援行動裝置響應式樣式（`@media (max-width: 760px)` 及 `@media (max-width: 430px)`）與減少動態效果設定（`prefers-reduced-motion`）。

## 3. 驗收期間已修正之 UI 缺陷

在驗收測試過程中，審查發現並修復了以下 UI 狀態缺陷：

1. **物種參考卡片跨潛點殘留問題**：
   - **缺陷**：原先 `map.js` 在 `loadSpeciesReferenceImages()` 發起非同步 fetch 時，未即刻清空畫面，導致在慢速網路或切換至無資料潛點時，前一潛點的物種卡片短暫殘留在畫面上。
   - **修正**：在取得請求 token 後立即調用 `clearSpeciesReferenceDisplay()` 與 `setSpeciesReferenceBusy(true)`，切換時即刻清空前次卡片與聲明，完全消除異步競爭與視覺殘留。
2. **潛點名稱與代表點座標讀取路徑對齊**：
   - **修正**：將後端 API 與前端測試針對 `dive_sites` 根屬性 `name`、`latitude`、`longitude` 與 `administrative_area` 的鍵值讀取邏輯完整對齊，消除因資料庫欄位別名不同導致的潛在空字串風險。
